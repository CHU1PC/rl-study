# 強化学習の基礎（社内輪講会 2026-10-05）

「強化学習は、報酬で重み付けした教師あり学習として読める」という1本の筋で、Q学習と方策勾配法をつなぎます。

| ファイル | 中身 |
| --- | --- |
| `rl_study/gridworld/` | デモ1: 迷路の Q学習。価値がゴールから広がる様子を見せる。比べるための、迷路の方策勾配法もある |
| `rl_study/curling/` | デモ2とハンズオン: カーリングの的当て。方策勾配法と、区切った表の Q学習を並べる |
| `rl_study/style.py` | 2つのデモが共通で使う、図の色と日本語フォントの選び方 |
| `rl_study/playback.py` | 2つのデモが共通で使う、「止める／再開」「進める」「最初から」のボタン |

2つのデモは、役割ごとにファイルを分けています。

```text
rl_study/gridworld/
├── __main__.py   入口（python -m rl_study.gridworld で動く）
├── env.py        迷路そのもの。1手進めて、次のマスと報酬を返す
├── agent.py      ε-greedy と Q学習。1手ごとの記録も残す
├── viewer.py     デモの画面。記録した手を1手ずつ再生し、変わった見込みの更新の式を出す
├── draw.py       盤面（マスごとの4方向の見込み）の描画、4コマの PNG と GIF の書き出し
├── reinforce.py  比べるための方策勾配法（REINFORCE）。マスごとの確率の表を学ぶ
└── compare.py    Q学習と方策勾配法を10回ずつ学習させて、最短の道を学べたかを数える

rl_study/curling/
├── __main__.py         入口（python -m rl_study.curling で動く）
├── env.py              的当てそのもの。向きと強さから、石が止まる位置と的までの距離を返す
├── policy_gradient.py  方策勾配法。向きと強さの平均とばらつきを学ぶ
├── table.py            向きと強さを区切った表の Q学習
├── record.py           1回の学習の記録（投数ごとの的までの距離）。届いた投数を調べる
├── draw.py             的と石の描画、距離の推移のグラフ
├── compare.py          方策勾配法と Q学習、ハンズオンの設定を10回ずつ学習させて比べる
└── play.py             ハンズオンの入口。画面のスライダーで設定を変えて学習させ、学習曲線を重ねて比べる
```

## デモ1: 迷路の Q学習

```bash
uv run python -m rl_study.gridworld
```

ウィンドウが開き、最初の40エピソードを1手ずつ再生します。最後まで流すと35秒ほどです。

| 画面の部品 | 中身 |
| --- | --- |
| 左の盤面 | マスを4つの三角に分けて、上・右・下・左へ動いたときの見込みを数字と色で出す。青はプラス、オレンジはマイナス、太字はそのマスで一番大きい見込み。黒い丸は今いるマス、線はそのエピソードで通った道 |
| 右の文字 | エピソードと手数、ここまでの結果（ゴール、落とし穴、時間切れの回数）、直前に変わった見込みの更新の式 |
| 「止める」と「再開」 | 再生を止める、続ける |
| 「1手進める」 | 再生を止めて、1手だけ進める |
| 「最初から」 | エピソード1に戻して、再生し直す |

見込みが変わらない手は早送りで流れます。見込みが変わった手では、その三角を太い枠で囲んで少し止まります。
最初の7エピソードはゴールに着かず、見込みは8エピソード目からゴールの隣のマスに付き始めます。
10エピソード目には、その1つ手前のマスに 0.225 が付きます（y = 0 + 0.9 × 0.5 = 0.45、Q ← 0 + 0.5 × (0.45 − 0) = 0.225）。
16エピソード目には、Q が一番大きい手を選ぶだけで最短の8手で着くようになります。
上の道は12手の遠回りなので、学習後は下の8手の道を選びます。
実際には10回に1回（ε＝0.1）無作為に動くので、50エピソード以降も大半は8〜12手でゴールに着き、約5%は X に落ちて終わります。

| オプション | 既定 | 意味 |
| --- | --- | --- |
| `--episodes` | 300 | 回すエピソード数。画面で再生するのは最初の40エピソードまで |
| `--seed` | 0 | 乱数の種 |
| `--save DIR` | なし | ウィンドウを出さず、`gridworld_snapshots.png`（4コマ）と `gridworld_q.gif`（1エピソード1コマ）を DIR に書き出す |

核になるのは `agent.py` の `q_learning` の中の2行です。

```python
target = step.reward + (0.0 if step.done else gamma * q[step.next_cell].max())
q[cell][action] += alpha * (target - q[cell][action])
```

同じ迷路を方策勾配法（`reinforce.py`）でも学習させて、seed 0〜9 で比べると次のようになりました。
「学べた」は、値が一番大きい向きだけを選んで、最短の8手でゴールに着くことです。
Q学習は1エピソードごとに、方策勾配法は1回の更新（16エピソード）ごとに判定しています。方策勾配法のエピソード数は16刻みになります。

| 方法 | 学べた回数 | 学べるまでのエピソード数（中央値） |
| --- | --- | --- |
| Q学習 | 10回中10回 | 14 |
| 方策勾配法 | 10回中6回 | 840 |

```bash
uv run python -m rl_study.gridworld.compare
```

## デモ2: カーリングの的当て

```bash
uv run python -m rl_study.curling
```

石を投げる向き（−45〜45度）と強さ（0〜1、強さ1で10m進む）を決め、前方6m、右12度にある的の中心に近く止めるほど報酬が高くなります。
報酬は、的の中心までの距離に負号を付けたものです。
投げるたびに向きと強さに少しぶれが入るので、中心を狙っても平均0.19m外れます。

ウィンドウに3つの図が並び、方策勾配法の1回の更新（16投）ごとに1コマ進みます。最後まで流すと13秒ほどです。
下のボタンで、「止める／再開」「1回進める」「最初から」を操作できます。

| 図 | 中身 |
| --- | --- |
| 左 | 方策勾配法の1回の更新。下の「左の図の見方」のとおり |
| 中央 | Q学習。向きと強さを区切った候補の止まる位置（灰色の点）と、投げた石 |
| 右 | 2つの方法の、狙いで投げたときの的までの距離の推移 |

左の図は、方策がどう更新されたかを見せます。ハンズオンの画面の左の図も同じです。

| 左の図の見方 | 中身 |
| --- | --- |
| 青い石 | その回の平均より的に近かった石。重み A が正なので、その行動を出やすくする |
| オレンジの石 | 平均より遠かった石。重み A が負なので、その行動を出にくくする。ベースラインを外すと、全部の石がオレンジになる |
| 点線と実線の輪 | 更新の前と後の、方策のばらつきの範囲（ばらつきの2倍の所）。石は、これに加えて投げるたびのぶれでも散らばる |
| ×印と矢印、細い線 | ×印は更新後の狙い（平均）。矢印は今回の更新での動き、細い線はここまでに狙いが通った道 |
| 図の上の数字 | 狙いとばらつきを、向き（度）と距離（m）で「更新前 → 更新後」の形で出す。的は向き12度、距離6m |

| オプション | 既定 | 意味 |
| --- | --- | --- |
| `--throws` | 800 | 投げる数。16 の倍数に切り下げる |
| `--bins` | 20 | Q学習で、向きと強さをそれぞれ何段階に区切るか（2 以上） |
| `--seed` | 0 | 乱数の種 |
| `--save DIR` | なし | ウィンドウを出さず、`curling.gif` を DIR に書き出す |

seed 0〜9 で回すと、次のようになりました。数字は中央値で、かっこの中は10回の最小と最大です。

| 方法 | 候補の数 | 0.5m 以内に届いた投数 | 800投の最後の距離 | 3,200投の最後の距離 |
| --- | --- | --- | --- | --- |
| 方策勾配法 | 区切らない | 224（208〜256） | 0.25m（0.20〜0.41） | 0.22m（0.20〜0.31） |
| Q学習 5×5 | 25 | 届かない | 1.43m | 1.43m |
| Q学習 10×10 | 100 | 届かない | 0.61m | 0.61m |
| Q学習 20×20 | 400 | 152（32〜432） | 0.30m（0.29〜0.32） | 0.30m（0.30〜0.31） |
| Q学習 40×40 | 1,600 | 88（16〜272） | 0.38m（0.24〜0.51） | 0.24m（0.23〜0.27） |

```bash
uv run python -m rl_study.curling.compare
uv run python -m rl_study.curling.compare --throws 3200
```

Q学習は区切った候補の点にしか止められないので、区切りが粗いと、何投かけても的に寄りきれません。
細かく区切ると候補が増えて、全部を試し終えるまでの投数が増えます。
40×40 は800投では候補の半分までしか試せず、3,200投かけて方策勾配法に並びます。
方策勾配法は区切らないので、区切りの数を選ぶ必要がありません。

0.5m 以内に届くのは、Q学習の方が早い回が多くなりました。
Q学習の狙いは「投げた候補のうち、見込みが一番大きいもの」なので、的の近くの候補をたまたま早く投げると、その時点で近づくためです。
行動が向きと強さの2種類だけなら、区切った Q学習でも十分に使えます。

Q学習の見込みは、その候補で得た報酬の平均です（学習率を、その候補を投げた回数の逆数にしています）。
まだ投げていない候補は見込みが分からないので、狙いには選びません。

方策勾配法の損失は、迷路の `reinforce.py` と同じ形です。
分類の cross-entropy の代わりに、正規分布の −log π(a) を使います。

```python
advantages = (rewards - rewards.mean()) / (rewards.std() + 1e-8)
loss = (-dist.log_prob(actions).sum(dim=1) * advantages).mean()
```

ばらつきには 0.02 の下限を付けています。
下限が無いと、投げる数を増やしたときにばらつきが 0 近くまで縮み、狙いが流れ出します（3,200投で最後が 0.19〜1.40m）。

## ハンズオン: 設定を変えてカーリングを学習させる

```bash
uv run python -m rl_study.curling.play
```

ウィンドウが開きます。左に方策の更新の図（見方はデモ2と同じ）、右に学習曲線、下にスライダーとボタンが並びます。

1. 何も変えずに「学習する」を押す
2. スライダーを1つだけ動かして、もう一度「学習する」を押す
3. 前に回した設定の曲線が残るので、重ねて比べる

1回5秒ほどです。「曲線を消す」を押すと、`runs/curling/` の記録を消して最初からやり直せます。

学習の途中で「止める」を押すと、その回の更新を見せたまま止まります。
「1回進める」を押すと、止めたまま更新を1回だけ進めます。学習していないときに押すと、止めた状態で学習を始めて、最初の更新を見せます。
「再開」で続きを流します。
記録は `runs/curling/` に残り、次に起動したときも直近の5本を重ねて描きます。

| 画面のつまみ | 既定 | 選べる値 | 意味 |
| --- | --- | --- | --- |
| 学習率 | 0.02 | 0.001〜0.3 の9段階 | 狙い（平均）を1回の更新で動かす大きさ。ばらつきの学習率は 0.1 に固定 |
| 1回の更新に使う投げの数 | 16 | 2、4、8、16、32、64 | 何投の結果をまとめて1回更新するか |
| 投げる数の合計 | 800 | 200、400、800、1,600、3,200 | 1回の学習で投げる数。更新の回数は、合計を「1回の更新に使う投げの数」で割った数になる |
| ベースライン（平均を引く） | 入れる | 入れる、外す | 外すと、平均を引かず、報酬をそのまま重みにする |

投げる数の合計が違う曲線を重ねたときは、横軸を一番長い曲線に合わせます。
凡例には「学習率 0.02 / 更新ごと 16投 / 合計 800投」の形で設定が出ます。

起動するときの引数で、つまみの最初の値と、画面では変えない値を決められます。

| オプション | 既定 | 意味 |
| --- | --- | --- |
| `--lr` | 0.02 | 学習率の最初の値。画面で選べる9段階のどれか |
| `--batch` | 16 | 1回の更新に使う投げの数の最初の値 |
| `--throws` | 800 | 投げる数の合計の最初の値。画面で選べる5段階のどれか |
| `--no-baseline` | なし | 最初からベースラインを外しておく |
| `--sigma` | 0.25 | 最初のばらつき（向きと強さで同じ値、0.05〜1.5）。画面では変えない |
| `--seed` | 0 | 乱数の種。同じ種と同じ設定なら、同じ曲線になる |
| `--clear` | なし | `runs/curling/` の過去の実行（記録の JSON と、画面なしで残した PNG）を消してから始める |

ウィンドウを出せない環境（`MPLBACKEND=Agg` など）では、引数の設定で1回だけ学習させて、記録（JSON）と図（PNG）を `runs/curling/` に残します。
この記録も、次にウィンドウを開いたときに、前に回した曲線として重ねて描きます。

seed 0〜9 で回すと、次のようになりました。変えた値だけを書いていて、他は既定のままです。数字は中央値で、かっこの中は10回の最小と最大です。

| 設定 | 0.5m 以内に届いた投数 | 最後の的までの距離 |
| --- | --- | --- |
| 既定 | 224（208〜256） | 0.25m（0.20〜0.41） |
| 学習率 0.1 | 48（48〜144） | 0.31m（0.24〜0.54） |
| 学習率 0.005 | 768（10回中8回が届いた） | 0.40m（0.35〜0.51） |
| 更新ごと 4投 | 80（56〜108） | 0.27m（0.23〜0.45） |
| 更新ごと 64投 | 届かない（10回とも） | 0.63m（0.60〜0.71） |
| 合計 200投 | 届かない（10回とも） | 0.73m（0.65〜0.96） |
| 合計 3,200投 | 224（208〜256） | 0.22m（0.20〜0.31） |
| ベースラインなし | 464（288〜688） | 0.30m（0.20〜0.45） |
| 学習率 0.005、合計 3,200投 | 768（768〜816） | 0.21m（0.19〜0.27） |
| 更新ごと 64投、合計 3,200投 | 832（10回とも832） | 0.21m（0.20〜0.27） |

ゆっくり学ぶ設定は、合計を 3,200投にすれば10回とも届きます。
800投では、更新ごと 64投は1回も届かず、学習率 0.005 は10回中2回が届きません。
